## 2. 결정 사항

### 2.1 표 구조

- 제작 확정 수량 변경에 따라 `1-2. 제작 확정 목록 (35종)`으로 제목을 갱신한다.
- 현재 편집본의 `3-1. 실물 대비 형태 검수`는 No 01~35의 개별 행을 사용한다.
- 3-1 에셋명은 `01_PPE_...`가 아니라 `PPE_...`부터 기록한다.
- `실물과의 차이`, `영향`, `판정`은 사용자가 작성할 수 있도록 빈칸으로 둔다.
- 3-1 열 너비는 No 42px, 에셋명 175px, 판정 88px로 두어 서술 칸을 확보한다.
- 3-2와 5-1은 No 열을 유지하고 에셋명 셀의 `01_` 형식 숫자 접두사만 제거한다.
- 5-1의 No와 파일명 사이 이미지 열 및 35개 이미지 첨부·해제 영역은 유지한다.

### 2.2 편집본과 HTML 저장본 분리

편집 원본에서는 다음 기능을 제공한다.

- 텍스트와 표 셀 편집
- 표 행 추가·복제·삭제·순서 변경
- 일반 스크린샷 영역의 파일 첨부·교체·삭제
- 이미지 드래그앤드롭과 클립보드 붙여넣기
- 5-1 이미지 열의 첨부·교체·해제
- 자동 저장, JSON/HTML/PNG/MD/PDF 출력

HTML 저장본은 `data-standalone-snapshot="true"`인 읽기 전용 문서로 구분한다.

- 편집 초기화를 실행하지 않는다.
- 상단 편집 도구, 행 조작 UI, 이미지 첨부·해제 UI를 숨긴다.
- 저장본의 스크린샷과 5-1 이미지를 터치하거나 클릭하면 전체 화면으로 확대한다.
- 확대 화면은 배경, `닫기` 버튼 또는 `Esc`로 닫는다.
- 키보드 사용자는 이미지에 포커스한 뒤 `Enter` 또는 Space로 확대할 수 있다.

### 2.3 저장본 데이터 독립성

- HTML 저장 시 현재 DOM의 텍스트와 Base64 이미지를 파일에 직접 포함한다.
- 각 저장본에 고유한 저장 키를 부여한다.
- 편집 원본의 IndexedDB 또는 Local Storage가 저장본의 내장 내용을 덮어쓰지 않는다.
- 저장본은 v9 레거시 저장 영역을 조회하지 않고 JSON 없이 단독으로 연다.

### 2.4 범용 빈 템플릿

`에셋기획서_템플릿.html`은 문1~문5의 제목, 표 헤더, 스크린샷 영역과 편집 도구만
남긴다.

- 각 표에 작성을 시작할 수 있는 빈 행 하나를 둔다.
- 내장 이미지와 PPE 에셋 작성값은 포함하지 않는다.
- `asset-plan-blank-template-v1` 전용 저장 영역을 사용한다.
- v9/v10 레거시 데이터 복원을 명시적으로 차단한다.
- 템플릿에서 생성한 HTML 저장본에도 읽기 전용 이미지 확대 모드를 적용한다.

### 2.5 PDF 출력

- v10과 빈 템플릿의 상단 도구에 `PDF 출력` 버튼을 둔다.
- 버튼을 누르면 현재 편집 내용을 자동 저장하고 `window.print()`를 호출한다.
- 인쇄 기준은 A4 세로, 12mm 여백이다.
- 편집 도구, 행 조작 UI, 이미지 삭제 버튼과 편집 외곽선은 출력하지 않는다.
- 브라우저 인쇄 창에서 `PDF로 저장`을 선택해 파일을 생성한다.

### 3.1 35번째 행 후속 수정

- 기존 브라우저 저장 데이터의 제목이 `(34종)`이어도 복원 직후
  `1-2. 제작 확정 목록 (35종)`으로 보정한다.
- `+ 행`은 일반 셀만 비우고, 5-1의 `.asset-image-cell`에는 이미지 미리보기,
  첨부, 해제 및 붙여넣기 안내 구조를 다시 만든다.
- 단순 숫자만 사용하는 `No` 표에서 새 행의 번호가 비어 있으면 행 위치와 기존 번호를
  기준으로 사용하지 않은 번호를 입력한다. 기존 `01~34` 번호는 변경하지 않는다.
- `05·06 PPE 진열장`처럼 `No` 열을 에셋 참조 설명으로 사용하는 표는 자동 채번에서
  제외한다.
- 페이지 초기화와 저장용 DOM 복제 시점에 빈 번호를 함께 확인하므로, 이미 저장된
  빈 35번째 셀도 다시 열면 복구되고 자동 저장된다.

## 4. 완료한 검증

- v10 3-1의 34개 행, No 01~34, `PPE_` 에셋명과 빈 작성 셀을 정적으로 확인했다.
- 3-2와 5-1의 에셋명 숫자 접두사가 0건이고 No 열이 유지됨을 확인했다.
- 5-1 이미지 첨부·해제 영역 34개를 확인했다.
- 복구 저장본에 3-1 작성 행 34개와 내장 이미지 43개가 남아 있음을 확인했다.
- 빈 템플릿에 카드 5개, 표 10개, 스크린샷 영역 4개, 5-1 이미지 셀 1개가 있고
  내장 이미지와 PPE 작성값이 없음을 확인했다.
- HTML 세 파일의 인라인 JavaScript 문법을 Node.js `new Function` 기준으로 확인했다.
- v10과 빈 템플릿에 PDF 버튼, A4 인쇄 규칙과 `window.print()` 호출이 연결됨을
  확인했다.
- 현재 편집본의 제목이 `(35종)`이며, 저장 데이터 복원 뒤에도 같은 제목을 적용하는
  경로를 확인했다.
- 빈 35번째 `No` 셀이 `35`로 복구되고, 두 번째 실행에서는 불필요한 변경이 없으며,
  설명형 `No` 표는 건드리지 않는 기능 테스트를 완료했다.
- 현재 편집본의 인라인 JavaScript 문법과 Downloads 반영 파일의 SHA-256 일치를
  확인했다.

## 5. 남은 수동 검증

현재 세션에서는 연결 가능한 브라우저가 없어 실제 화면 클릭·터치 검증은 수행하지
못했다.

1. 편집 원본에서 스크린샷과 5-1 이미지의 첨부·교체·해제를 확인한다.
2. 텍스트와 이미지를 입력한 뒤 HTML 저장본을 생성하고 JSON 없이 다시 연다.
3. 저장본에서 편집 UI가 보이지 않고 이미지 터치 확대와 닫기가 동작하는지 확인한다.
4. 저장본을 닫고 다시 열어 내장 텍스트와 이미지가 유지되는지 확인한다.
5. PDF 출력에서 페이지 분할, 넓은 5-1 표, 이미지 크기와 한글 글꼴을 확인한다.

정적 HTML·JavaScript 검증을 실제 브라우저 터치 동작 또는 PDF 시각 품질 검증으로
확대 해석하지 않는다.
