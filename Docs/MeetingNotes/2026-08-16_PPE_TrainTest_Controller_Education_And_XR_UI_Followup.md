## 오늘 확정한 동작

- 키보드의 UI A와 오른손 컨트롤러 물리 A는 모두 상세 컨트롤러 교육에 진입한다.
- 상세교육을 보지 않은 새 세션은 `이름 제출 → Controller Simp → CardIntro`로 진행한다.
- 상세교육을 완료한 사용자는 키보드로 복귀하며, 이후 이름 제출 시 간단교육을 건너뛰고
  `CardIntro`로 바로 진행한다.
- 상세교육 완료 뒤에도 물리 A 또는 UI A로 상세교육을 다시 볼 수 있다.

## 컨트롤러 가이드 이미지 회귀

### 증상

- 상세 Trigger 단계에서 오른쪽 하단 이미지가 표시되지 않았다.
- 상세교육 뒤 간단교육으로 진입하면 가이드 이미지가 표시되지 않는 경우가 있었다.

### 근본 원인

- Clip별 작성 가이드 그룹을 활성화한 뒤 기존 상태별 자식 토글이 `1_Ray/Panel`을 다시 껐다.
- 상세교육에서 변경된 자식 활성 상태가 남아 같은 그룹을 사용하는 간단교육에도 영향을 줬다.

### 적용한 변경

- 상세교육과 간단교육 모두 Clip별 작성 가이드 그룹을 표시 상태의 단일 기준으로 사용한다.
- 이미지 쌍은 다음과 같다.
  - Trigger: `1_Ray`의 `Card`·`Panel` + `1_Ctrl_Trigger`
  - Grip: `2_Marker` + `2_Ctrl_Grip`
  - Joystick: `3_Ray_T` + `3_Ctrl_Joystick`
- 씬과 Inspector의 RectTransform, 크기, 위치, 색, Sprite는 덮어쓰지 않았다.

### 고스트핸드 결정

- 고스트핸드는 현재 결함이나 이번 수정의 완료 조건으로 분류하지 않는다.
- PPE Item Marker의 오른쪽 배치는 유지한다.
- 후속 구현에서는 실제로 잡은 손을 기준으로 왼손 잡기에는 왼손 투명 고스트핸드,
  오른손 잡기에는 오른손 투명 고스트핸드 및 손 포즈가 적용되도록 설계한다.
- 현재 씬에는 `GhostHandPose`와 `ControllerGrabHandPose` 연결이 없으므로, 기존 Grab과 손 모델을
  고스트핸드가 이미 동작하는 것으로 간주하지 않는다.
- 고스트핸드 후속 작업 전까지 기존 Marker-only Grab, Toggle Grip, Action Panel 및 장착 판정을
  변경하지 않는다.

### 이번 후속 적용 결과

1. 방호복 착용 전 장갑·장화 사용 승인을 차단했다.
2. 마스크 `확인하기` 완료 전 사용·폐기를 차단하고 상태 변경 시 확인을 초기화했다.
3. Action Panel의 네 결과 문구를 사진 기준으로 통일했다.
4. 안전모 교육·정상 Grab 음성을 기존 음원에 연결했다.
5. PPE/태블릿 미완료 음성 분리는 교육 모드에만 적용했다. 훈련·테스트 정책은 유지했다.

  확인하고, Quest/OpenXR에서 안전모 및 미완료 음성의 실제 타이밍을 별도로 확인해야 한다.

## 퀴즈 레이아웃 고정 폰트·콘텐츠 높이 대응 시험

### 결정과 근본 원인

- 교육·훈련·테스트 페이지의 RectTransform은 원래 모두 같은 값이었다. 긴 문구를 높이 100의
  질문 영역과 높이 54의 선택지 라벨에 넣으면서 Auto Size가 문항마다 서로 다르게 축소된 것이
  불균일한 화면의 주원인이었다.
- 첫 시험에서는 모든 문항에 최대 높이를 미리 배정했다. 사용자 화면 확인 결과 짧은 교육 문항도
  질문과 첫 선택지 사이에 큰 빈 공간이 생겨 의도와 맞지 않았다.
- 수정 기준은 `짧은 문항은 기존 기본 간격`, `긴 문항만 실제 콘텐츠 높이만큼 확장`이다.

### 수정 적용

- `_1` 씬의 작성 기준값을 Canvas `1200×600`, Panel `1000×560`, 질문 `900×100`, 선택지
  `860×64`, 선택지 라벨 `790×54`, 피드백 `780×90`으로 복구했다.
- 글꼴은 질문 24pt, 선택지 22pt, 피드백 20pt 고정값을 유지했다.
- `PPEQuizController`가 TMP `preferredHeight`를 측정해 작성된 최소 높이보다 긴 경우에만 다음을
  수행한다.
  - 질문 높이를 필요한 만큼 늘린다.
  - 기존에 작성된 요소 간 간격을 유지한 채 선택지와 피드백을 아래로 이동한다.
  - 선택지 문구가 두 줄 이상이면 해당 라벨과 버튼만 필요한 만큼 높인다.
  - 콘텐츠 하단 여백을 유지하도록 Canvas와 Panel을 아래 방향으로 필요한 만큼만 확장한다.
- 동적 레이아웃의 패딩값은 런타임 상수가 아니라 `_1` 씬의 직렬화값으로 작성했다.
  - 질문 세로 패딩 12
  - 선택지 세로 패딩 8
  - 피드백 세로 패딩 12
- 문항 원문, 정답, 채점, SFX, 피드백 조건과 XR Button 입력 경로는 변경하지 않았다.

### 조정·원복 경로

- 적용: `Tools > PPE > Quiz Layout Trial > Apply Adaptive Fixed Font (_1)`
- 원복: `Tools > PPE > Quiz Layout Trial > Restore Baseline (_1)`
- 검사: `Tools > PPE > Quiz Layout Trial > Validate Adaptive Fixed Font (_1)`
- 기존 콘텐츠 설정 도구는 씬에 작성된 글꼴 정책을 다시 덮어쓰지 않으며 페이지별 Progress 참조를
  명시적으로 연결한다.

### 검증 상태와 수동 확인

- Runtime/Editor 보조 전체 빌드는 오류 0개로 통과했다. 기존 패키지·SourceGenerator 경고는
  남아 있다.
- `_1` 씬의 기본 RectTransform, 고정 TMP, 적응형 설정과 다섯 Progress 참조를 정적으로 검사한다.
- Unity에서 짧은 교육 문항이 기존 간격으로 표시되는지 먼저 확인한다.
- 이어서 훈련의 긴 질문·정답 피드백, 테스트 5번 종합문제와 네 번째 선택지가 잘림·겹침 없이
  아래로 확장되는지 확인한다.
- Quest/OpenXR에서는 확장된 하단 선택지 접근성과 양안 가독성을 별도로 확인하고 필요하면 씬의
  직렬화 패딩값을 조정하거나 원복한다.

### 테스트 Q5 강제 줄바꿈 확인

- 테스트 모드 5번 종합문제가 가로 폭에 비해 약 5줄로 표시되는 현상을 확인했다.
- 원인은 적응형 레이아웃이나 고정 글꼴이 아니라 Q5 `Prompt` 원문에 문장 단위 강제 줄바꿈
  (`\n`)이 여러 개 포함된 것이다.
- 수정 대상은 `_1` 씬의 `Quiz Canvas > PPE Quiz Controller > Authored Test Questions >
  Element 4 > Prompt`와 `PPETrainTestQuizContentSetup.TestQuestions[4]` 원문이다.
- 중간 강제 줄바꿈을 공백으로 바꾸고 TMP 자동 줄바꿈에 맡긴다. 질문 영역·글꼴·적응형 패딩은
  변경하지 않는다.
- 현재는 원인과 수정 위치만 확인한 상태다. 실제 문구 수정 후 2~3줄 표시 여부를 Game View와
  Quest/OpenXR에서 확인하기 전까지 완료로 처리하지 않는다.

## 사용자 통합 테스트 음성 메모

### 기록 상태

- 사용자가 교육 모드를 직접 진행하며 실제 재생된 내레이션을 따라 말하는 중간에 UI 조정 의견과
  재현 현상을 함께 음성으로 전달했다. 따라서 입력 내용에는 `재생 나레이션`과 `사용자 테스트
  메모`가 섞여 있다.
- 이 절은 받아쓰기 및 분류 기록이다. 아래 항목은 아직 코드·씬·오디오를 수정하지 않았으며,
  원음과 실제 이벤트 순서를 대조하기 전에는 완료로 처리하지 않는다.
- 아래 번호는 최종 나레이션 재생 순서를 확정한 것이 아니다. 문장 자체는 나레이션 후보로,
  위치·분리·변경·종료 필요 표현은 사용자 테스트 메모로 임시 분류했다.

### 시작·컨트롤러 가이드 구간

1. 이름 입력 후 바로 안전 교육을 시작하려면 Enter를 누르고, 자세한 컨트롤러 조작 교육이
   필요하면 A 버튼을 누르도록 안내한다.
2. 상세 가이드 진입 문구: `먼저 컨트롤러 사용법을 확인하겠습니다.`
3. 메뉴·버튼 선택에는 A 버튼, 선택 동작에는 Trigger 버튼을 사용한다는 설명이 들린다.
   두 표현이 같은 UI 선택을 가리키는지 원음과 실제 입력 매핑을 대조해야 한다.
4. 잡을 수 있는 물건에는 작은 반짝임의 Item Marker가 있고, 손을 Marker에 댄 뒤 Grip을 짧게
   한 번 눌러 잡고 옮긴다고 설명한다.
5. 이동 가능 장소에는 바닥의 큰 화살표와 반짝임이 나타난다고 설명한다.

### 컨트롤러·모드 UI 조정 의견

- 컨트롤러 가이드에서 `이동`과 `이동 레이` 설명을 한 단계에 묶지 말고 두 단계로 분리한다.
- 미니 컨트롤러 가이드를 현재 위치보다 왼쪽으로 이동할 필요가 있다.
- `밀폐 공간 진입 전 안전 교육` 타이틀을 `PPE 착용 교육`으로 바꿀지 검토한다.
- 교육·훈련·테스트 세 모드 버튼의 왼쪽에 각 모드의 특징과 차이를 설명하는 영역이 필요하다.

### PPE 교육 진입·태블릿 구간

1. `PPE 착용 교육을 시작합니다.`
2. 맞은편 PPE 진열장 바닥 앞의 이동 Marker를 안내하고 왼쪽 위치 Marker 쪽으로 이동시킨다.
3. `PPE 환복 장소에 도착했습니다.`
4. PPE 착용 중 설명을 잘 들으면 학습 마지막에 같은 형태의 퀴즈가 나온다고 안내한다.
5. `이제 작업 내용을 확인하고 PPE를 착용해 보겠습니다.`
6. 태블릿을 Grip으로 잡아 작업계획서 내용과 필요한 PPE 복장을 확인하도록 안내한다.
7. 필요한 PPE 전체 착용과 태블릿 작업계획서의 체크·서명이 교육 완료 조건이라고 설명한다.
8. 이상이 없다면 방호복 상단 패널에서 왼쪽 컨트롤러 Trigger로 `사용` 처리하고, 문제가 있으면
   하자 PPE로 판단해 다시 관찰한 뒤 올바른 버튼을 선택하도록 안내한다.

### PPE 처리 중 반복 청취 문구

- `왼쪽부터 차례로 처리해 보겠습니다.`
- 하자 PPE: `하자가 있는 PPE입니다. 다시 관찰 후 올바른 버튼을 선택해 주세요. 폐기는 A
  버튼입니다.`
- 정상 PPE: `정상 PPE입니다. 다시 관찰 후 올바른 버튼을 선택해 주세요. 사용은 Trigger
  버튼입니다.`
- 성공 처리: `올바르게 착용되었습니다. 다음 PPE를 선택해 주세요.`
- 테이프: 장갑과 방호복, 또는 장갑·장화를 함께 착용하지 않으면 사용할 수 없다는 안내가
  재생된다.
- 장갑: 손가락 끝까지 잘 맞아야 정상 PPE라는 안내가 재생된다.
- 안전모: 머리에 수평으로 맞추고 턱끈을 고정해야 한다는 안내가 재생된다.
- 마스크: 먼저 `확인하기`로 호흡 소리를 확인하고, 얼굴 밀착면에 머리카락이나 방호복 후드가
  끼지 않았는지, 송기호스가 꺾이거나 눌리지 않았는지, 공기가 정상 공급되는지 확인하도록
  안내한다.
- 안전대 안내는 전달 음성에서 `양쪽 어깨끈과…` 이후 문장이 끊겨 원음 재청취가 필요하다.

### 완료 구간 청취 문구

- `작업이 마무리됐습니다. 조이스틱으로 오른쪽 위치 마커로 이동해 주세요.`
- `작업에 필요한 PPE를 모두 성공적으로 착용하셨습니다.`
- `이제 교육 정리 전 미니 퀴즈로 학습 의도를 체크해 보겠습니다.`
- `PPE 착용 교육을 무사히 완료하였습니다. 수고하셨습니다.`

### 통합 테스트에서 재현된 잔여 현상

1. 다른 구간으로 텔레포트한 뒤에도 이전 구간의 SFX가 계속되며, 구간 이탈 시 즉시 종료되어야
   한다.
2. 태블릿 체크·서명 시퀀스가 여러 번 실행된다. 한 교육 세션에서 허용할 재실행 정책과 현재
   Trigger 중복 수신 여부를 확인해야 한다.
3. 태블릿을 놓을 때 체크·서명 완료 여부와 무관하게 방호복 착용 안내 음성이 다시 재생된다.
   기존 설계는 교육 세션 최초 해제에서만 1회 재생하는 것이므로 실제 1회 상태와 세션 초기화
   경로를 대조해야 한다.

### 원음 확인이 필요한 받아쓰기

- 이동 Marker 설명 중 `큰 네이 화살표`, `큰 네이이 세계`로 인식된 부분은 정확한 단어를
  확정하지 않았다. 원본 음원을 다시 듣고 문구를 교정한다.
- 전달 중 `숨기 마스크`, `방호복 코드`, `안전벨`로 인식된 표현은 각각 `송기마스크`, `방호복
  후드`, `안전대`일 가능성이 있으나 원음 확인 전에는 원문으로 확정하지 않는다.

## 훈련 모드 통합 테스트 음성 메모

### 나레이션 후보

- `훈련 모드를 선택하셨습니다.`
- `훈련 모드를 시작하겠습니다. PPE 진열장으로 이동해 주세요.`
- `작업 내용 확인과 그 작업에 필요한 PPE 착용을 진행합니다.`

  호출인지 재생 로그로 구분해야 한다.

### UI·동작 메모

- 모드 모달의 하늘색 버튼이 지나치게 쨍해 다른 요소보다 과도하게 눈에 띈다.
- 훈련·테스트 버튼도 선택 가능한 활성 버튼인데 현재 어두운 색 때문에 비활성처럼 보인다.
  세 모드의 활성 상태가 동일하게 읽히도록 버튼 색상 체계를 통일하되, 선택 상태는 별도 상태
  색으로 구분할 필요가 있다.
- 훈련 모드에서 장화를 잡거나 처리할 때 교육 모드 전용 멘트가 재생됐다. 장화 이벤트의 모드
  분기와 교육 음성 호출 경로를 확인해야 한다.

### 나레이션 후보

- `테스트 모드를 선택하셨습니다.`
- `테스트 모드를 시작합니다.`
- `PPE 작업 테스트 무사히 완료됐습니다. 수고하셨습니다.`

### UI·동작 메모

- 마스크 애니메이션을 변경할 필요가 있다. 어떤 동작·속도·상태를 바꿀지는 다음 관찰에서
  구체화한다.
- 테스트 모드에서도 장화 교육 멘트가 재생됐다. 교육 전용 음성이 훈련·테스트 양쪽으로 누출되는
  동일 결함 후보로 분류한다.
- 테스트 결과 값이 `00` 형식으로 보이는 경우 앞쪽의 `0`을 제거할 필요가 있다는 의견이
  전달됐다. 점수·정답 수·오답 수·시간 중 어느 필드인지 화면을 다시 보고 확정한다.
- 음성 입력의 `공공처럼 앞쪽에 있는 공`은 `00처럼 앞쪽에 있는 0`을 뜻하는 것으로 추정하되,
  대상 필드 확인 전에는 최종 문구로 확정하지 않는다.

## 레이 레티클 통합 테스트 메모

- `PP 패널`에 레이가 닿았을 때 레티클 크기가 최초 표시 상태보다 매우 작아져 눈에 잘 띄지
  않는 현상이 관찰됐다.
- `PP 패널`이 PPE Action Panel을 뜻하는지는 다음 확인에서 확정한다.
- 패널 진입 전·Hover 중·패널 이탈 후의 레티클 크기를 각각 비교하고, UI Hit 상태에서만 적용되는
  동적 스케일 또는 별도 레티클 프리팹 전환이 있는지 확인한다.
- 이 항목은 관찰 기록이며 아직 원인 추적·수정·Quest/OpenXR 재검증 전이다.

## 한글 키보드 Shift 표시 개선 의견

- 현재 Shift를 누르면 쌍기역 등 Shift 대상 글자가 기존 키의 위쪽 보조 레이블로 표시된다.
- 사용자 의견은 보조 글자를 추가 표시하는 방식보다 Shift 상태에서 기존 키의 주 레이블 자체를
  교체하는 방식이다. 예: `ㄱ → ㄲ`, `ㅂ → ㅃ`, `ㅈ → ㅉ`, `ㄷ → ㄸ`, `ㅅ → ㅆ`,
  `ㅐ → ㅒ`, `ㅔ → ㅖ`.
- Shift 해제 또는 한 글자 입력 후 Shift가 해제되는 정책에 맞춰 기본 레이블로 복구해야 한다.
- 입력 자모 매핑은 유지하고 시각 레이블 전환만 변경하는 방향이며, 아직 구현·Quest 입력 검증
  전이다.

## 방호복 선행 조건 후 장갑·장화 교육 음성 재안내 의견

- 방호복을 입지 않은 상태에서 장갑이나 장화를 처음 잡으면 교육 멘트가 재생되지만, 실제 사용은
  방호복 선행 조건으로 차단된다.
- 사용자는 방호복 위치로 돌아가 방호복을 입은 뒤 다시 장갑·장화 위치로 와야 하므로, 최초
  시도에서 1회 교육 음성을 소비하면 정상 착용 시점에는 안내를 다시 들을 수 없다.
- 제안 흐름은 다음과 같다.
  1. 방호복 미착용 상태의 최초 장갑·장화 Grab에서 기존 교육 안내를 재생한다.
  2. `방호복 착용 후 재안내 대기` 상태를 남긴다.
  3. 방호복 착용을 완료하고 돌아와 해당 PPE를 처음 정상 Grab하면 같은 교육 안내를 추가 1회
     재생하고 대기 상태를 해제한다.
  4. 이후 Grab에서는 반복 재생하지 않는다.
- 좌·우 장갑 및 좌·우 장화가 각각 상태를 가질지, 장갑군·장화군 단위로 공유할지와 재생 대상이
  개별 PPE 교육 음성인지 방호복 선행 경고 음성인지는 구현 전에 확정해야 한다.
- 현재는 사용자 흐름 개선 의견이며 아직 구현·Play Mode·Quest 청취 검증 전이다.

## 한쪽 장갑 상태에서 테이프 사용 후 반대쪽 장갑 시각 미반영

### 재현 순서

1. 방호복을 착용한다.
2. 장갑을 한쪽만 착용한다.
3. 이 상태에서 테이프를 사용해 테이핑 처리를 완료한다.
4. 이후 나머지 반대쪽 장갑을 착용한다.

### 관찰과 기대 결과

- 먼저 착용한 장갑은 테이핑된 핸드 모델로 표시되지만, 나중에 착용한 반대쪽 장갑은 테이핑되지
  않은 핸드 모델로 남았다.
- 테이프 사용 완료 상태가 유지되고 있다면 이후 장착되는 반대쪽 장갑에도 테이핑 시각 상태가
  즉시 반영되어야 한다.
- 개선 시 테이프 사용 시점의 현재 장착 손만 변경하지 말고 `테이프 처리 완료`를 지속 상태로
  보존한 뒤, 좌·우 장갑 장착 이벤트에서도 해당 상태를 다시 적용해야 한다.
- 장화도 한쪽만 착용한 상태에서 테이프를 먼저 사용한 뒤 반대쪽을 장착했을 때 같은 문제가
  발생하는지 확인한다.
- 아직 원인 추적·수정·Play Mode·Quest 손 모델 검증 전이다.

## 중간 이탈용 EXIT 텔레포트 존 제안

- 사용자의 현재 위치 가까이에 일반 진행 Marker와 구분되는 `EXIT` 텔레포트 존을 한 개 더 두어,
  교육·훈련·테스트 진행 중에도 사용자가 시나리오에서 빠져나갈 수 있는 루트가 필요하다는 의견이
  나왔다.
- EXIT 존은 진행 목적지가 아니라 중도 종료 입력이므로 색상·레이블·형태를 일반 텔레포트 존과
  명확히 구분해야 한다.
- 후속 설계에서 다음을 확정한다.
  - EXIT 존의 정확한 위치와 각 PPE 구간에서의 접근 가능 여부
  - 즉시 종료 또는 확인 모달을 거치는지
  - 복귀 목적지가 모드 선택 화면인지 최초 시작 위치인지
  - 종료 시 재생 중 Voice·SFX·BGM, 퀴즈·모달, PPE Grab과 텔레포트 상태를 어디까지 초기화할지
  - 테스트 점수·진행 기록을 폐기할지 중도 종료로 별도 기록할지
- 실수로 일반 이동 중 EXIT를 선택하지 않도록 별도 확인이나 입력 유지 시간이 필요할 수 있다.
- 현재는 동선 개선 제안이며 아직 오브젝트 생성·상태 전이 구현·Quest/OpenXR 검증 전이다.

## 단계별 자체 QA 문서 재구성

- 지금까지의 교육·훈련·테스트 관찰과 개선 의견을 기존 기준 문서
  `Docs/PPE_HandTest_EndToEnd_QA.md`에 `_1` 씬 전용 단계별 자체 QA로 통합했다.
- 단계는 `시작 → 키보드 → 컨트롤러 교육 → 시나리오 카드 → 모달 → PPE 진열장 앞(텔레포트 1)
  → 태블릿 → 방호복 → PPE 앞(텔레포트 2) → 거울(텔레포트 3) → 퀴즈` 순서다.
- 테스트 결과와 중도 EXIT는 흐름 종료 검증을 위해 `결과·종료` 보조 단계로 분리했다.
- 별도의 날짜형 QA 작업일지는 만들지 않고, 오늘 수행 사실과 결정은 이 회의록에 유지하며 QA
  항목의 기준과 다음 실행 결과는 기존 QA 문서에 누적한다.
