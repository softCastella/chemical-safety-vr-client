# PPE 훈련 퀴즈 모드 구분 및 종료 페이드 속도

## 재현

1. `Assets/Scenes/3_PPE_Room_Train_Test.unity`에서 테스트 시작 Override를 모두 끈다.
2. 훈련 모드를 선택하고 PPE·태블릿·거울 단계를 완료한다.
3. 훈련 퀴즈와 종료 후 복귀 연출을 확인한다.

## 증상

- Director의 활성 모드는 `Training`으로 유지됐지만 교육용 5문항이 그대로 표시됐다.
- 테스트 원문은 4지선다인데 기존 Quiz Canvas의 각 페이지에는 버튼이 3개뿐이었다.
- 종료 Fade Canvas의 작성값이 `0.75`초여서 훈련 종료감을 주기에는 암전 속도가 너무 빨랐다.

## 근본 원인

- 새벽 세션에서 전달된 별도 훈련·테스트 문항 원문이 기준 회의록에 기록되지 않았고, 구현 시 기존 교육 5문항을 공용으로 사용한다는 잘못된 전제가 남았다.
- 대상 씬에는 교육용 질문·보기·정답만 존재했고 `PPEQuizController`에도 모드별 문항 은행이 없었다.
- 기존 `PPEQuizPage`는 질문 TMP와 보기 TMP를 직렬화 참조하지 않고 버튼 3개와 교육 정답·해설만 보유해 런타임에서 별도 문항을 안전하게 표시할 수 없었다.
- 종료 페이드 시간은 `PPEFinaleController.m_FadeDuration`의 씬 직렬화 값 `0.75`초를 사용하고 있었다.

## 적용 변경

- 교육용 5문항은 기존 TMP 작성값으로 보존하고, 훈련 5문항과 테스트 5문항을 `PPEQuizController`의 별도 씬 직렬화 문항 은행으로 추가했다.
- 훈련은 이미지의 상황형 3지선다와 문항별 상세 정답 피드백을 사용한다. 오답은 정답을 노출하지 않고 같은 문항에서 재선택한다.
- 테스트는 이미지의 4지선다를 사용하며 첫 선택만 채점한다. 즉시 정오답 아이콘·SFX·텍스트·해설은 모두 숨기고 자동 진행한다.
- `Tools > PPE > Apply Training Test Quiz Content`를 명시적으로 실행해 Unity가 각 페이지에 `Option 4`와 직렬화 FileID를 생성하도록 했다. YAML에 임의 FileID를 직접 추가하지 않았다.
- 질문과 보기 TMP에는 씬 작성 Auto Size 값을 적용했다. 런타임은 모드별 텍스트와 활성 상태만 바꾸며 RectTransform·폰트·크기를 지정하지 않는다.
- 단방향 페이드 시간을 늘리는 방식은 사용자가 의도한 효과가 아니었다. 예전 교육모드 복귀와 동일하게 작성값 `0.75`초의 페이드아웃 뒤 암전 중 복귀하고, `0.75`초 페이드인으로 공간을 연 다음 `2_Mode`를 표시하도록 복원했다.
- 검증 하네스가 페이지별 질문 참조, 4개 버튼·라벨, 테스트 전용 네 번째 버튼의 초기 비활성 상태, 두 문항 은행의 문항 수·보기 수·정답 배열과 `Fade-out → 암전 복귀 → Fade-in → 모드 모달` 순서를 검사하도록 확장했다.

## 영향 범위

- 교육 퀴즈의 문항·선택지·정답·상세 해설은 유지한다.
- 훈련·테스트 문항의 기준 원문은 `Docs/MeetingNotes/2026-08-14_PPE_Room_HandTest_Meeting.md`의 16.10에 기록했다.
- 테스트용 `Option 4` 다섯 개와 해당 TMP 라벨만 새 씬 오브젝트로 추가했다. 교육·훈련에서는 비활성화된다.
- 기존 XR Button 입력 경로, Result Canvas, 텔레포트, PPE Grab, 태블릿과 거울 판정은 변경하지 않았다.

## 검증

- Unity GUI에서 콘텐츠 적용 메뉴의 성공 로그를 확인했고 디스크 씬에 훈련·테스트 각 5문항, 페이지별 4개 버튼·라벨과 정답 배열이 저장된 것을 정적으로 확인했다.
- Runtime/Editor 보조 빌드에서 오류 0개를 확인했다. 기존 패키지·SourceGenerator 경고는 남아 있다.
- Unity에서 `Tools > PPE > Validate Train Test Modes`를 실행해 11개 모드 음원, 모드 버튼, 퀴즈·결과 참조, 별도 문항 은행과 정답 배열, 테스트 전용 네 번째 버튼, 거울 재검사와 종료 복귀 조건의 PASS를 확인했다.
- Quest/OpenXR에서 훈련 3지선다·상세 피드백·오답 재선택, 테스트 4지선다·무즉시피드백·점수와 `TRAIN_007 → 0.75초 페이드아웃 → 암전 복귀 → 0.75초 페이드인 → 2_Mode`를 확인해야 한다.

## 2026-08-16 메인 병합 후 잔여 관찰

아래 항목은 메인 병합본의 사용자 통합 실행에서 확인된 잔여 결함이다. 이번 기록에서는 코드·씬 수정이나 근본 원인 진단을 수행하지 않았다.

### 교육 모드

- 좌·우 장갑 각각에서 같은 교육 안내가 재생되어 장갑 교육 멘트가 총 두 번 나온다. 기존 회의록의 `10.1 좌·우 장갑 안내 중복`에 기록된 미적용 결함이 메인 병합본에서도 남아 있음을 확인했다.
- PPE Action Panel에서 `사용할 수 없음` 안내와 `깨끗한 PPE 정책` 안내가 상황에 맞게 분리되지 않고 혼용되어 등장한다. 어느 이벤트·상태·PPE에서 각 안내가 선택되는지는 아직 추적하지 않았다.

### 훈련·테스트 모드

- Quiz Panel의 `Q.1` 등 문항 표기와 본문·선택지 레이아웃이 페이지마다 일정하지 않다.
- 일부 문항은 콘텐츠 영역이 지나치게 좁거나 중앙 정렬로 보이고, 일부 문항은 Auto Size에 의해 폰트가 과도하게 작아진다.
- 특히 훈련 모드에는 질문·선택지·피드백을 포함한 전체 상하 레이아웃이 무너져 보이는 문항도 있었다.

### 후속 확인 범위

- 장갑 좌·우 입력이 공유 교육 음성을 각각 호출하는 경로와 1회 재생 상태를 확인한다.
- PPE Action Panel의 상태 판정부터 피드백 문구·음성 선택까지 전체 이벤트 경로를 모드별로 대조한다.
- 퀴즈 페이지별 작성 RectTransform, 정렬, Auto Size 범위와 Play Mode에서의 런타임 활성화·텍스트 교체 경로를 함께 비교한다.
- 교육·훈련·테스트를 각각 재현해 수정 전 기준 화면을 확보한 뒤, Game View와 Quest/OpenXR에서 별도로 재검증한다.

## 2026-08-16 퀴즈 레이아웃 시험 적용

### 근본 원인 확인

- 다섯 페이지의 RectTransform 작성값은 동일했다.
- 높이 100의 질문 영역과 높이 54의 선택지 라벨에서 Auto Size 범위가 질문 `14~31`, 선택지
  `18~25`로 열려 있어, 런타임에서 들어오는 문구 길이에 따라 페이지별 글꼴 크기가 달라졌다.
- `PPEQuizController`는 모드 전환 시 텍스트와 활성 상태만 변경했다. 런타임 위치·크기·글꼴
  덮어쓰기가 원인은 아니었다.

### 적용 변경과 영향 범위

- `3_PPE_Room_Train_Test_1.unity`에만 패널을 아래로 확장하고 바깥 여백과 요소 간 간격을 확보했다.
- 질문 24pt, 선택지 22pt, 피드백 20pt의 고정 글꼴을 적용했다.
- 원본 씬, 문항 원문, 정답, 채점, SFX, 피드백 표시 조건, XR Button 입력 경로는 변경하지 않았다.
- 적용·원복·검사 메뉴를 `PPETrainTestQuizContentSetup`에 추가했으며, 기존 콘텐츠 설정 실행이
  작성된 Auto Size 정책을 다시 덮어쓰지 않도록 수정했다.

### 검증

- 정적 검사에서 `_1` 씬의 모든 대상 RectTransform/TMP 값과 원본 씬 무변경을 확인했다.
- Runtime/Editor 보조 빌드 오류 0개를 확인했다.
- Unity 연결 시간 초과로 TMP 실제 글리프 기준 높이 검사, Game View 및 Quest/OpenXR 표시는 아직
  확인하지 못했다. 세 모드의 5개 문항을 실제로 확인한 뒤 조정 또는 원복 여부를 결정한다.

### 사용자 화면 확인 후 수정

- 고정 확장 시험은 짧은 교육 문항에도 높이 200의 질문 영역을 미리 배정해 질문과 첫 선택지
  사이에 불필요한 빈 공간을 만들었다.
- `_1` 씬의 기본 높이와 간격을 복구하고 고정 글꼴은 유지했다.
- TMP의 실제 콘텐츠 높이가 작성된 최소 높이를 초과할 때만 질문·선택지·피드백과 패널 하단이
  순차적으로 늘어나는 적응형 레이아웃으로 변경했다.
- 패딩은 씬 직렬화값이며 원본 씬에는 적응형 레이아웃을 활성화하지 않았다.

### 테스트 Q5 강제 줄바꿈 잔여 항목

- 테스트 Q5는 원문에 여러 강제 줄바꿈이 저장되어 충분한 가로 폭에서도 약 5줄로 표시된다.
- `_1` 씬의 `testQuestions[4].prompt`와 편집기 콘텐츠 정의의 동일 원문을 함께 수정해야 한다.
- 레이아웃 크기나 글꼴을 다시 축소하지 않고 강제 줄바꿈만 제거해 TMP 자동 줄바꿈 결과를
  확인한다.
- 이 항목은 아직 수정·Game View·Quest/OpenXR 검증 전이다.

### 테스트 결과 앞자리 0 표시 의견

- 테스트 결과의 숫자 값이 `00` 형식으로 표시될 때 앞자리 `0`을 제거해야 한다는 사용자 의견이
  기록됐다.
- 현재 음성 메모만으로는 대상이 점수, 정답 수, PPE 오답 수, 분·초 중 어느 필드인지 확정할 수
  없다. 결과 화면을 다시 확인해 대상 필드와 원하는 예시를 확정한 뒤 수정한다.

## 2026-08-26 카드 안내 1회 재생 및 종료 복귀 경로 통합

대상 씬은 `Assets/Scenes/3_PPE_Room_3mode_loco.unity`이다.

### 적용한 변경

- `CardIntro` 안내 음성은 애플리케이션 실행 중 최초 진입에서만 소비한다. 카드 상세 모달에서
  되돌아오거나 동일 컴포넌트에서 흐름을 다시 시작해도 음성을 다시 재생하지 않는다.
- `CardIntro` 음성이 끝난 뒤 반복 음성 루틴을 시작하지 않는다. 카드 선택 UI는 그대로 유지되며
  실제 카드 선택만 상세 모달을 여는 기존 입력 경로를 보존한다.
- 교육·훈련의 정상 완료, 테스트 결과 화면의 뒤로가기, 중도 종료가 모두
  `ShowModeChoicesAfterCompletionReturn()`을 사용한다.
- 기존 직렬화 이벤트와의 호환을 위해 남겨 둔 `ShowScenarioCardsAfterCompletionReturn()`도
  카드 목록을 직접 열지 않고 동일한 모드 선택 복귀 메서드로 위임한다.

### 근본 원인과 영향 범위

- `CardIntro`는 상호작용 대기 상태라 재진입할 때마다 기본 음성과 반복 음성을 다시 시작할 수
  있었다. 실행 수명 동안 유지되는 별도 1회 상태가 없었던 것이 원인이다.
- 정상 완료의 주 경로는 이미 모드 선택 모달을 호출했지만, 카드 목록을 직접 복원하는 구형 공개
  메서드가 함께 남아 있어 완료 호출자가 달라지면 복귀 화면이 갈릴 수 있었다.
- 카드 위치·Canvas·버튼·XR Raycaster·텔레포트 입력과 모드 모달의 Inspector 작성값은 변경하지
  않았다.

### 검증

- `PPETrainTestModeValidationHarness`에 정상 완료의 주 경로 및 구형 완료 진입점이 모두 모드 선택
  메서드로 수렴하는지, `CardIntro`가 1회 상태를 소비하고 반복 재생으로 들어가지 않는지 검사하는
  정적 조건을 추가했다.
- Unity Play Mode에서는 최초 카드 접근 시 안내 1회, 카드 상세에서 뒤로가기 후 무음, 교육·훈련
  정상 종료 후 모드 선택 모달, 테스트 결과 뒤로가기 후 모드 선택 모달을 확인해야 한다.
- Quest/OpenXR 런타임 확인은 아직 필요하다.

## 2026-08-28 훈련·테스트 PPE 판정 피드백 분리

### 적용한 변경

- 교육모드에서만 시나리오 필수 PPE의 How-To와 잘못된 PPE 관련 Voice를 허용한다.
- 훈련모드는 PPE 사용·폐기 SFX와 일반 진행 Voice를 유지하되 How-To, 잘못된 PPE Voice,
  빨간 판정 문구 및 구형 성공·오류 아이콘을 표시하지 않는다.
- 테스트모드는 PPE 판정 SFX와 판정 문구·아이콘을 모두 표시하지 않는다. 기존 하네스가 요구하는
  모드 시작, PPE 구역 이동, 정상 종료 Voice와 중도 퇴장 Voice는 유지한다. 테스트 퀴즈의 정오답
  SFX·설명·아이콘은 기존 무음 정책을 보존한다.
- 발걸음·서명 SFX는 판정 피드백이 아니므로 테스트에서도 기존 동작을 유지한다. 테스트 점수 기록,
  모달 완료, 텔레포트 및 결과 화면 전이도 변경하지 않았다.

### 근본 원인과 영향 범위

- 패널이 모드 처리보다 먼저 공통 판정 표시·SFX·지연 오답 Voice를 실행했고, 훈련 분기에서 빨간
  문구와 구형 아이콘을 다시 활성화했다.
- `PPEVoiceFlowDirector`의 모드별 허용 속성을 단일 기준으로 두고 패널이 표시·SFX·Voice 직전에
  확인하도록 변경했다. 씬 및 Prefab의 작성 위치·크기·색 등 표시 작성값은 변경하지 않았다.
- 현재 로코모션 씬의 활성 헬멧 패널 `PPE_A_Helmet_Strap`, `PPE_A_Helmet_NoStrap`에는 기존
  `PPEVoiceFlowDirector` 참조가 비어 있어 모드 정책을 직접 확인하지 못했다. 두 활성 패널에 씬의
  기존 Director FileID를 연결했으며 Transform·Collider·표시 작성값은 변경하지 않았다.

### 검증

- `PPELocomotionPpeRegressionValidationHarness`에 교육 `SFX/오답 Voice 허용`, 훈련
  `SFX만 허용`, 테스트 `둘 다 금지`, 훈련의 구형 오답 Voice 호출 금지 및 테스트 전용

- Unity Play Mode에서 교육·훈련·테스트 각각의 PPE 사용·폐기, 오답 PPE, 필수·불필요 PPE Grab을
  비교하고 Quest/OpenXR에서 실제 출력과 UI 숨김을 확인해야 한다.

## 2026-08-28 시나리오·모드별 퀴즈 풀과 5문항 무작위 출제

### 대응 요청과 보존 동작

- 화학보안경, 안면보호대, 니트릴 내부장갑 문항을 누락 없이 포함하되 현재 작업계획에 필요한 PPE
  문항만 출제한다.
- 교육·훈련·테스트의 기존 정답 처리, 피드백 정책, 테스트 결과 점수와 5페이지 UI는 유지한다.
- 시나리오별 후보가 5문항보다 많으므로 세션을 시작할 때 5문항을 무작위로 확정하고, 퀴즈 도중에는
  다시 섞지 않는다.

### 적용한 변경

- `PPEQuizQuestionCatalog` ScriptableObject를 추가하고 `작업계획 × 학습모드` 여섯 풀을 분리했다.
- 밀폐공간은 화학보안경·안면보호대 문항을 제외하고 안전대·송기마스크·공통 내부장갑 문항을 포함한다.
- 누출대응은 안전대·송기마스크 문항을 제외하고 화학보안경·안면보호대·공통 내부장갑 문항을 포함한다.
- 후보 수는 밀폐공간 `교육 7 / 훈련 6 / 테스트 7`, 누출대응 `교육 9 / 훈련 8 / 테스트 7`이다.
- `PPEVoiceFlowDirector`가 `ActiveLearningMode`와 `ActiveWorkPlan`을 함께 전달한다.
- `PPEQuizController`는 PPE 주제를 먼저 섞어 가능한 한 서로 다른 주제에서 한 문제씩 선택한 뒤,
  남은 자리를 중복 문항 없이 채운다. 화면의 `Q1~Q5` 번호는 선택 완료 뒤 현재 페이지 기준으로 붙인다.
- `Tools > PPE > Validate Scenario Quiz Pools` 하네스를 추가해 여섯 풀, 최소 6문항, 보기 수,
  정답 범위, 시나리오 금지 주제, 내부장갑·화학보안경·안면보호대 포함과 작업계획 전달을 검사한다.

### 검증

- 새 Runtime/Editor 소스를 포함한 `dotnet build chemical-safety-vr-client.slnx --no-restore`는 오류
  0개로 통과했다. 저장소 기존 폐기 API 및 직렬화 필드 경고는 남아 있다.
- 검증 중 대상 씬의 `2113142500` 직렬화 블록부터 약 4,400줄이 누락되고
  `m_PrefabInstance:/rHideFlags`가 들어간 손상 상태를 발견했다. 해당 FileID 구간만 마지막 커밋의
  정상 블록으로 복구했으며, 오늘의 PPE 위치·명칭·오디오·퀴즈 참조 등 다른 씬 변경은 보존했다.

  시작해 5문항 고정, 재시작 시 조합 변경, 금지 PPE 미출제를 확인해야 한다.
