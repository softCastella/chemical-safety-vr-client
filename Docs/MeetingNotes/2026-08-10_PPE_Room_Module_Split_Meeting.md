# 2026-08-10 PPE Room 모듈 분기·씬 구성 회의록

- 프로젝트: `Prototype_Tyche_Jinyoung`
- 작성일: 2026-08-10
- 안건: 컨트롤러 교육과 안전교육 분기, PPE Room 씬 부하 대응, 입력 버튼 의미 정리, 음원 제작 순서
- 상태: 설계 결정 완료, 구현 전

## 1. 현재 상황

현재 PPE Room에는 XR Origin, 월드 UI, PPE 상호작용, 음성, 거울 카메라·RenderTexture, 퀴즈와 시나리오 카드가 함께 들어 있다. 따라서 씬의 실행 부하가 완전히 없는 상태는 아니며, 모듈을 한 씬에 모두 넣고 비활성화하는 방식은 메모리와 씬 로딩을 완전히 분리하지 못할 수 있다.

교육 콘텐츠는 다음 세 가지 안전교육 모드를 포함한다.

- 교육모드
- 훈련모드
- 테스트모드

컨트롤러 안내 음원은 처음 사용하는 사람을 전제로 하므로 구체적인 설명이 필요하다. 설명을 억지로 줄이지 않고 안전교육과 독립된 모듈로 분리한다.

## 2. 결정 사항

### 2.1 두 씬으로 분리

실행 시 선택한 씬만 로드하도록 다음 구조를 사용한다.

```text
Title/Bootstrap
├─ PPE_Room_Controller
└─ PPE_Room_Safety
```

- 기존 PPE Room 흐름은 안전교육 씬의 기준으로 보존한다.
- 컨트롤러 씬은 컨트롤러 설명, 연습용 PPE, 최소 상호작용만 포함한다.
- 컨트롤러 씬에는 안전교육 시나리오 카드, 퀴즈, 거울 카메라·RenderTexture, 안전교육 전용 진행기와 음원을 포함하지 않는다.
- 씬 전환은 `LoadSceneMode.Single`을 기준으로 하여 이전 씬의 Canvas, AudioSource, XR 입력 소비자가 남지 않게 한다.
- 두 씬은 동일한 Input Action Asset과 공통 PPE Prefab을 참조한다. 씬별로 입력 설정이나 에셋 원본을 복제하지 않는다.

### 2.2 타이틀과 안전교육 모드 선택

타이틀에는 버튼 두 개를 둔다.

```text
컨트롤러 교육 → 컨트롤러 씬 로딩
안전교육      → 모드 선택 모달
```

안전교육 버튼을 누르면 새 화면으로 이동하지 않고 같은 타이틀 위에 모드를 선택하는 모달을 표시한다.

```text
[교육모드]
[훈련모드]
[테스트모드]
[취소]
```

모드는 PPE Room에 진입하기 전에 확정한다. PPE Room 내부의 시나리오 상세 모달에서는 모드를 다시 선택하지 않고 `시나리오 시작`만 제공한다.

### 2.3 컨트롤러 교육 흐름

```text
웰컴
→ 컨트롤러 상세 설명
→ 연습용 PPE를 그립으로 한 번 잡기
→ 트리거로 상태 확인
→ 착용·폐기 버튼 기능 안내
→ 종료 멘트
→ 타이틀 복귀
```

컨트롤러 씬의 목적은 조작법 학습이다. PPE 안전 판단, 착용 순서, 거울 확인과 퀴즈는 안전교육 씬에서만 다룬다.

### 2.4 안전교육 흐름

#### 교육모드

```text
교육 웰컴
→ VR 키보드 이름 입력
→ 이름 제출 완료
→ 짧은 컨트롤러 안내
→ 시나리오 카드
→ 상세 모달
→ 시나리오 시작
→ PPE 검사·착용
→ 거울
→ 퀴즈
→ 결과·복귀
```

이름 입력 키보드는 교육모드에서만 활성화한다. 이름 제출 이벤트 이후에만 다음 음성과 상태로 전이한다.

#### 훈련모드

```text
훈련 웰컴
→ 시나리오 카드
→ 상세 모달
→ 시나리오 시작
→ PPE 수행
→ 결과·복귀
```

교육모드보다 짧은 지시와 제한적인 힌트를 사용한다.

#### 테스트모드

```text
테스트 웰컴
→ 시나리오 카드
→ 상세 모달
→ 시나리오 시작
→ 힌트 없이 PPE 수행
→ 점수·결과
→ 복귀
```

### 2.5 컨트롤러 입력 의미

모든 모드에서 입력 의미를 동일하게 유지한다.

```text
Grip       장비 잡기
Trigger    장비 확인·검사
B          착용
A          폐기
```

UI의 `B 사용` 표기는 PPE 동작이 분명한 `B 착용`으로 변경한다.

- PPE를 잡고 있지 않을 때 Trigger는 카드·모달·키보드 UI 선택에 사용한다.
- PPE를 잡고 검사 가능한 상태일 때만 Trigger를 검사 입력으로 해석한다.
- 양손 입력을 지원하면 왼손의 X/Y에도 같은 의미를 매핑한다. 오른손만 지원하면 컨트롤러 교육에서 이를 명시한다.

## 3. 음원 제작 원칙

컨트롤러 음원은 긴 설명을 유지하되, 사용자 행동을 기다릴 수 있도록 단계별 Clip으로 분리한다.

```text
CTRL_01_Welcome
CTRL_02_ControllerOverview
CTRL_03_GripGrab
CTRL_04_TriggerInspect
CTRL_05_BWear
CTRL_06_ADiscard
CTRL_07_Complete

EDU_01_Welcome
EDU_02_NameInputGuide
EDU_03_NameConfirmed
EDU_04_ControllerBrief

TRN_01_Welcome
TST_01_Welcome
```

사용자 작업은 최종 스크립트 수정과 ElevenLabs 음원 생성이다. 음원은 구현된 상태 전이와 행동 성공 이벤트에 맞춰 연결한다.

## 4. 3D 에셋 문서 확인 결과

기존 [`Docs/PPE_Room_AI_3D_Asset_Naming_Plan.md`](../PPE_Room_AI_3D_Asset_Naming_Plan.md)는 AI 3D 에셋의 분류, 명명, Prefab, GUID 보존 기준을 다루는 문서다. 이번 모듈 분기 문서가 아니므로 내용을 수정하지 않는다.

이번 작업에서는 다음 기준으로 해당 문서를 적용한다.

- 컨트롤러 씬과 안전교육 씬에서 공통 PPE Prefab을 재사용한다.
- 씬 분리를 위해 에셋 이름, `.meta`, GUID를 변경하지 않는다.
- 컨트롤러 씬에는 필요한 연습용 PPE만 배치하고 안전교육 전용 3D 에셋은 포함하지 않는다.
- 신규 3D 에셋을 추가할 경우 기존 `PPE_[분류]_[영문명]_[번호]` 명명 규칙을 따른다.

## 6. 완료로 보지 않는 항목

- 씬 복제만으로 성능이 해결됐다고 판단하지 않는다.
- Unity Game View 확인만으로 Quest 양안과 컨트롤러 입력이 정상이라고 판단하지 않는다.
- 음원 파일을 넣었다는 사실만으로 상태 전이와 음성 순서가 완료됐다고 판단하지 않는다.
- 3D 에셋 명명 문서의 존재만으로 신규 에셋 배치가 완료됐다고 판단하지 않는다.

## 7. 현재 코드 기준 모드 구현 가능성

현재 프로젝트는 교육모드를 중심으로 한 PPE 진행 기반이 있으며, 세 모드가 완성된 상태는 아니다.

| 모드 | 현재 기반 | 추가 구현 범위 | 판단 |
|---|---|---|---|
| 교육모드 | 웰컴, 이름 입력, 컨트롤러 안내, 카드·상세 모달, PPE 착용, 거울, 5페이지 퀴즈 | 새 모드 선택 진입점과 교육용 음원 재배치 | 가장 빠르게 구현 가능 |
| 훈련모드 | `ScenarioDetailModal`의 훈련 선택, 미완료 PPE·일반 훈련 UnityEvent | 모드 상태, 짧은 지시, 힌트 정책, 전용 종료·결과 분기 | 기존 기능을 확장해 구현 |
| 테스트모드 | 퀴즈 정답·오답 처리 | 힌트 차단, 점수·시도·시간 기록, 결과 화면, 테스트용 음성 | 별도 평가 로직 필요 |

현재 `PPEVoiceFlowDirector`는 단일 진행 상태 열거형을 사용하며, `StartAtCardIntroForTesting`와 `StartAtModalDetailForTesting`는 사용자용 테스트모드가 아니라 개발 중 특정 지점부터 시작하기 위한 오버라이드다. 따라서 이 값을 실제 교육·훈련·테스트 모드로 재사용하지 않는다.

구현 순서는 교육모드 기준 흐름을 먼저 보존한 뒤, 모드 선택 상태를 추가하고 훈련·테스트의 음성·힌트·결과 정책을 분기하는 순서로 한다. 컨트롤러 전용 씬 분리는 공통 모드 상태와 안전교육 씬의 진입 흐름이 안정된 뒤 진행한다.

## 8. 3D 에셋 네이밍 변경 작업 파악

기존 기준 문서 [`Docs/PPE_Room_AI_3D_Asset_Naming_Plan.md`](../PPE_Room_AI_3D_Asset_Naming_Plan.md)를 기준으로, 이번 작업에서 처리해야 할 3D 에셋 변경 범위는 다음과 같다.

### 명명 규칙

```text
PPE_[분류]_[영문명]_[번호]
```

- `PPE`: PPE Room 프로젝트 에셋임을 나타낸다.
- `분류`: `A` 착용 장비, `B` 환경·소화 장비, `C` 작업·접촉 도구, `D` 안내·보조 모델 중 하나를 사용한다.
- `영문명`: 모델의 용도와 형태를 식별할 수 있는 영문명을 사용한다.
- `번호`: 같은 종류 또는 배치 위치가 여러 개일 때 `01`, `02` 순서로 구분한다.
- 좌우 분리 모델은 `_L_01`, `_R_01`처럼 좌우를 이름에 포함한다.
- 상태가 다른 모델은 `SuitHang`, `SuitWear`처럼 상태를 이름에 포함한다.

### 적용 대상

- 원본 FBX 파일명
- 생성된 Prefab 파일명
- 씬 Hierarchy의 PPE 루트 이름
- 에셋 목록과 제출용 패키지의 항목명

### 보존 조건

- 이름 변경 시 `.meta` 파일과 GUID를 보존한다.
- 이름 변경을 이유로 새 모델을 복제하거나 씬의 Transform을 재배치하지 않는다.
- 동일 PPE를 두 씬에서 사용할 경우 하나의 공통 Prefab을 참조한다.
- 모델의 상태·좌우·배치가 실제 시각 상태와 일치하는지 Unity Inspector에서 확인한다.
- 코드가 문자열 이름 검색에 의존하는지 먼저 확인하고, 가능한 경우 기존 직렬화 참조를 유지한다.

### 이번 모듈 분기에서의 적용

- 컨트롤러 씬은 기존 명명 규칙을 따르는 연습용 PPE만 사용한다.
- 안전교육 씬은 기존 PPE 배치와 상태 이름을 유지한다.
- 씬 분리는 에셋 이름 변경과 별개의 작업이며, 두 작업을 동시에 수행해 대규모 참조 변경을 만들지 않는다.
- 신규 에셋이 필요할 때만 명명 규칙에 맞춰 추가하고, 기존 에셋의 이름 변경은 목록 확정 후 별도 단계에서 수행한다.
