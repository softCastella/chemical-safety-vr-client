# 브랜드 홈페이지 및 VR 상세페이지 레이아웃 정리

- 작성일: 2026-08-26
- 대상 프로젝트: `Final_VR_Tyche_Pivot`
- 적용 범위: `server/public/site`

## 1. 작업 목적

브랜드 홈페이지를 기업 담당자와 일반 방문자가 함께 이해할 수 있는 홍보 페이지로 정리하고, 현재 제작 범위인 PPE 착용 교육 중심의 화학물질 안전훈련 VR 콘텐츠가 페이지 전반에서 일관되게 보이도록 구성한다.

## 2. 적용한 변경

### 홈페이지

- `Now on Tyche` 영역에 화학물질 안전훈련 VR 빅사이즈 배너를 전체 카드 기준으로 배치했다.
- VR 배너 왼쪽 정보 영역의 구성과 기존 배너 형식을 맞췄다.
- 문의 폼에 `문의 종류` 드롭다운을 추가했다.
  - 일반 문의
  - 비즈니스 문의
- 문의 폼의 입력 요소 스타일을 드롭다운까지 일관되게 적용했다.

### IMMERSA 페이지

- CTA 왼쪽 이미지 영역에 화학물질 안전훈련 VR 스퀘어 배너를 적용했다.
- 히어로 영역은 기존 VR 대표 이미지 구성을 유지했다.

### 화학물질 안전훈련 VR 상세페이지

- 상단의 `프로젝트 소개` 버튼을 제거했다.
- 상단 히어로 영역의 왼쪽에는 다음 정보를 배치했다.
  - `TYCHE IMMERSA / PROJECT 01`
  - `화학물질 안전훈련 VR`
  - PPE 확인·착용 교육 중심의 설명
- 오른쪽 이미지 바깥 위쪽에 프로젝트 뱃지를 배치했다.
- 뱃지는 오른쪽 정렬, 그림자 제거, 흐린 테두리 중심으로 정리했다.
- Meta Horizon 안내 문구와 카드는 이미지 아래에 유지했다.
- 히어로 하단에 얇고 흐린 그레이 구분선을 추가했다.
- `ppe_room`, `check_work`, `select_ppe`, `ppe_check`, `check_ppe` 에셋을 활용해 VR 교육 흐름을 소개했다.
- 페이지 하단에 문의하기 CTA를 유지했다.

### SPARK / LOOP 페이지

- 중앙 정렬 준비중 콘텐츠의 키커, 제목, 설명, 홈 이동 버튼 사이의 세로 간격을 넓혔다.
- 두 페이지에 공통 스타일로 적용했다.

### 사이트 타이포그래피

- 홈페이지, IMMERSA/VR, SPARK/LOOP, BRAND V2의 작은 라벨·상태·내비게이션·푸터 텍스트에 최소 12px 기준을 적용했다.
- 상세페이지의 작은 캡션과 히어로 뱃지도 12px로 맞췄다.

## 3. 표현 기준

- 현재 콘텐츠 범위는 PPE 착용 교육이다.
- 제작 중이 아닌 밀폐공간 교육이나 일반적인 안전훈련 전반을 현재 제공 범위처럼 표현하지 않는다.
- 방문자가 실제 체험 요소와 교육 흐름을 빠르게 파악할 수 있도록 이미지와 짧은 설명을 교차 배치한다.

## 4. 영향 범위

- 정적 브랜드 홈페이지와 관련 하위 페이지의 HTML/CSS 및 이미지 배치만 변경했다.
- Unity 클라이언트 런타임, XR 입력, 씬, 서버 API 동작은 변경하지 않았다.

## 5. 완료한 검증

- 수정 대상 HTML/CSS 파일의 구조와 선택자 적용 여부를 정적으로 확인했다.
- `git diff --check`를 실행했으며 작업 대상 파일에서 오류가 발생하지 않았다.

## 6. 아직 필요한 수동 검증

- 실제 브라우저에서 데스크톱·모바일 해상도의 히어로 간격과 뱃지 줄바꿈 확인
- 홈페이지 배너 전환 및 문의 폼 드롭다운 동작 확인
- 한글 폰트 로딩 상태와 12px 텍스트의 실제 가독성 확인

## 7. 신규 공통 홍보용 단일 페이지 변경 전 판단

- 이번 변경이 대응하는 사용자 요청: 기존 상세페이지를 덮어쓰지 않고 기업·일반 사용자가 함께 볼 수 있는 VR 공통 홍보용 단일 페이지 시안을 별도 경로에 만든다.
- 보존해야 하는 기존 동작: 현재 홈페이지, IMMERSA 페이지, 기존 `chemical-safety-training` 상세페이지, 문의 폼, Unity/XR 클라이언트 및 서버 API는 변경하지 않는다.

1. 기존 Inspector/씬 작성값을 보존하는가?
   - Unity 씬과 Inspector는 작업 범위 밖이며 변경하지 않는다. 기존 웹페이지의 작성값도 수정하지 않고 새 정적 페이지 하나만 추가한다.
2. 단일 기준 오브젝트와 상태 소유자는 무엇인가?
   - 새 페이지의 콘텐츠·레이아웃 기준은 신규 경로의 `index.html` 한 파일이다. 별도 런타임 상태는 두지 않는다.
3. 입력 이벤트, Interactor/Caster, Raycaster, Layer, Collider의 전체 경로는 무엇인가?
   - XR 입력은 사용하지 않는다. 브라우저 입력은 앵커 링크와 네이티브 `details/summary`만 사용하며, 기업 문의 CTA는 기존 홈페이지의 `#contact`로 이동한다.
4. 실패 시 런타임 자동 수리 대신 명확한 오류로 멈춰야 하는가?
   - 런타임 자동 생성·자동 수리·fallback을 추가하지 않는다. 에셋과 링크 누락은 정적 검증에서 오류로 확인한다.
5. UI·텔레포트·PPE Grab·거울·XR 양안 중 어떤 소비자가 함께 영향을 받는가?
   - 웹 데스크톱·태블릿·모바일 레이아웃과 기업·일반 사용자 메시지만 영향을 받는다. Unity UI, 텔레포트, PPE Grab, 거울, XR 양안에는 영향이 없다.
6. 변경 전 기준 실행과 변경 후 비교 실행은 무엇인가?
   - 변경 전 기준은 현재 `immersa/chemical-safety-training` 페이지다. 변경 후에는 신규 페이지의 HTML 구조, 내부 링크, 이미지 경로, 반응형 규칙을 비교하고 기존 페이지가 수정되지 않았는지 확인한다.
7. 정적 확인, Unity Editor 확인, Quest/OpenXR 확인 중 어디까지 실제로 검증했는가?
   - 변경 전에는 기존 HTML/CSS와 이미지 에셋을 정적으로 확인했다. 이번 웹 전용 작업에는 Unity Editor와 Quest/OpenXR 검증을 수행하지 않는다.

- 상단 Meta Horizon 안내가 실제 링크로 연결되지 않았고 제품 기본정보 영역은 공통 CSS에서 숨겨져 있었다.

### 영향 범위

- 신규 정적 HTML 한 파일만 추가했다.
- 기존 브랜드 홈페이지, IMMERSA 페이지, 기존 VR 상세페이지와 공통 CSS는 수정하지 않았다.
- Unity 클라이언트, XR 입력, 씬, 서버 API 및 문의 폼 동작에는 영향이 없다.

### 완료한 검증

- 신규 페이지에서 참조하는 이미지, 파비콘, 내부 페이지 링크가 모두 실제 파일에 연결되는지 확인했다.
- 페이지 내 ID 9개와 앵커 6개를 대조해 중복 ID, 누락된 대상, 빈 `href`가 없음을 확인했다.
- 이미지 8개에 모두 `alt`가 있고, FAQ 5개와 데스크톱·모바일 반응형 규칙이 포함됐는지 확인했다.
- 신규 페이지와 본 회의록에 대해 `git diff --check`를 실행해 공백 오류가 없음을 확인했다.
- 서버 전체 테스트는 `server/node_modules`가 없어 `express`를 불러오지 못했고, 기존 홈 캐러셀 테스트도 현재 배너 개수 차이로 실패했다. 신규 페이지의 정적 검증 결과와는 별도인 환경·기존 테스트 상태로 기록한다.

### 아직 필요한 수동 검증

- 키보드로 본문 바로가기, 페이지 내 이동, FAQ 열기·닫기 순서와 포커스 표시를 확인한다.
- 한글 시스템 폰트별 제목 줄바꿈과 기업·일반 사용자 문구의 가독성을 확인한다.
- 실제 배포 전 최종 지원 기기, Meta Horizon URL, 공개 일정이 확정되면 제품 정보와 CTA를 갱신한다.

## 9. 인게임 이미지 가로형 재구성 변경 전 판단

- 이번 변경이 대응하는 사용자 요청: 세로로 길게 쌓인 체험 구성을 줄이고 기존 16:9 인게임 이미지를 온전히 활용할 수 있는 가로형 페이지 리듬으로 수정한다.
- 보존해야 하는 기존 동작: 기존 페이지와 신규 시안의 기업·일반 사용자 메시지, 현재 PPE 교육 범위, 문의 링크, FAQ와 제품 정보는 유지한다.

1. 기존 Inspector/씬 작성값을 보존하는가?
   - Unity 씬과 Inspector, 기존 웹페이지는 변경하지 않는다. 신규 프로모션 시안의 작성값만 수정한다.
2. 단일 기준 오브젝트와 상태 소유자는 무엇인가?
   - 신규 프로모션 `index.html`이 계속 단일 기준이다. 체험 이미지 영역은 CSS 가로 스크롤 레일 하나가 소유한다.
3. 입력 이벤트, Interactor/Caster, Raycaster, Layer, Collider의 전체 경로는 무엇인가?
   - XR 입력은 없다. 가로 레일은 브라우저 기본 스크롤·터치 스와이프와 단계 앵커 링크만 사용한다.
4. 실패 시 런타임 자동 수리 대신 명확한 오류로 멈춰야 하는가?
   - 자바스크립트 자동 보정이나 fallback을 추가하지 않는다. 이미지 비율과 링크 대상은 정적 검증한다.
5. UI·텔레포트·PPE Grab·거울·XR 양안 중 어떤 소비자가 함께 영향을 받는가?
   - 신규 웹 시안의 체험 이미지 레이아웃과 데스크톱·모바일 스크롤만 영향을 받는다.
6. 변경 전 기준 실행과 변경 후 비교 실행은 무엇인가?
   - 변경 전 세로형 큰 이미지 1개와 2열 카드 4개 구성을 기준으로, 변경 후 5개 이미지를 같은 16:9 가로 레일에서 전체 노출하는지 비교한다.
7. 정적 확인, Unity Editor 확인, Quest/OpenXR 확인 중 어디까지 실제로 검증했는가?
   - HTML/CSS 정적 확인만 수행한다. Unity Editor와 Quest/OpenXR는 작업 범위 밖이다.
