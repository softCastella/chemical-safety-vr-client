# PPE HandTest 게임 흐름·XR 상호작용 QA

## 목적

이 문서는 `3_PPE_Room_HandTest_scale_0`의 교육 흐름을 실제 플레이어 관점에서 검증하기 위한 QA 기준이다. 단순히 UI나 음원이 “보이거나 들림”을 확인하는 것이 아니라, 한 이벤트가 한 번만 발생해야 하는지, 반복 안내가 의도된 것인지, 이전 상태의 이벤트가 뒤늦게 섞이는 로직 오류인지를 판정한다.

부하 요소별 기존·개선 방식과 Profiler 검증 기준은 [PPE HandTest 성능 검토](PPE_HandTest_Performance_Review.md)를 따른다.

## 대상 및 실행 전 조건

- 대상 씬: `Assets/Scenes/3_PPE_Room_HandTest_scale_0.unity`
- 우선 실행 환경: Meta Quest Link/OpenXR. Game View는 보조 확인용이며 XR Trigger, 양안, HMD 오디오는 Quest에서만 통과 판정한다.
- 각 테스트는 Play Mode를 새로 시작하고, 이전 테스트의 PPE 장착·텔레포트 상태를 이어받지 않는다.
- Console의 오류와 경고를 기록한다. 오류가 발생하면 다음 단계로 진행하지 않고 해당 케이스를 실패로 기록한다.

## 전체 의도 흐름

`시작 안내 → 이름/컨트롤러 안내 → 카드 선택 → 교육 선택 모달 → PPE 구역 텔레포트 → PPE 검사·착용 → 거울 확인 → 퀴즈/종료`

각 단계는 다음 단계에 필요한 UI, 입력, 텔레포트만 열어야 한다. 이전 단계의 패널·음성·반복 안내가 다음 단계에 남아 있으면 실패다.

## 음성 판정 원칙

| 유형 | 허용 기준 | 중복으로 판정하는 경우 |
| --- | --- | --- |
| 단계 시작 음성 | 해당 상태에 처음 진입할 때 1회 | 같은 상태에 다시 진입하지 않았는데 동일 clip이 즉시 다시 시작됨 |
| 반복 안내 음성 | 플레이어가 해당 단계에서 지정 시간 동안 입력하지 않을 때만 반복 | 입력/텔레포트가 이미 수락되었거나 다음 상태로 바뀐 뒤 이전 안내가 재생됨 |
| PPE 잡기 안내 | 해당 PPE를 처음 선택했을 때 1회, 다음 PPE를 선택하면 이전 음성은 중단 가능 | 같은 PPE를 그대로 잡고 있는 동안 다시 재생되거나, 이전 PPE의 지연 음성이 다음 PPE 안내 위에 겹침 |
| 정답/오답 피드백 | 버튼 선택 1회당 SFX와 해당 피드백 음성 1회 | 한 번의 클릭에 두 Voice가 재생되거나 선택 해제 후 지연 음성이 재생됨 |
| 텔레포트 도착 음성 | 각 authored 도착 지점마다 교육 1회차에 1회 | 같은 도착 지점을 재통과했을 때 다시 재생, 또는 한 번의 도착에 두 번 재생 |
| 완료/거울 안내 | PPE 완료 또는 mirror marker 도착의 최초 조건 충족 시 1회 | 다른 PPE 조작이나 같은 marker 재통과로 반복됨 |

중복인지 판단할 때는 clip 이름, 재생 시각, 그 순간의 현재 단계, 플레이어가 수행한 입력을 함께 기록한다. 서로 다른 의도의 SFX와 Voice가 함께 나는 것은 중복이 아니다. 동일 Voice가 겹치거나, 종료된 단계의 Voice가 늦게 나는 경우만 로직 오류로 기록한다.

## Action Panel 위치 판정 기준

사용자 의도는 방호복 패널을 기준으로 한다.

- 기준점: 대상 PPE Renderer Bounds의 정면 중앙.
- 높이: PPE 상단보다 약간 위. 모델과 패널이 관통하지 않아야 한다.
- 방향: PPE 정면과 같은 기준을 유지하며, 장비마다 뒤집히거나 옆을 보지 않아야 한다.
- 일관성: 마스크·장갑·장화·테이프 등에서 화면상 거리감과 높이가 크게 달라지지 않아야 한다.
- 구현 기준: 각 PPE의 scene-authored `Action Panel Pose`를 기준으로 한다. 공용 패널은 선택 시 해당 pose의 자식이 되며, local position `(0, 0, 0)` 및 local rotation `(0, 0, 0)`을 사용한다. Bounds 기반·viewer-facing 재계산은 사용하지 않는다.

## 결과 기록 양식

각 실패에는 다음을 남긴다.

- QA ID, 실행 일시, 빌드/Editor 여부, Quest 연결 상태
- 재현 절차와 실제 결과
- 기대 결과와의 차이
- 화면 또는 HMD 캡처, Console 로그
- 음성 문제라면 clip/대략 시각/현재 상태/직전 입력
- 위치 문제라면 PPE 이름, 패널 이름, Game·Scene·HMD 중 발생 View
- icon 문제라면 PPE 이름, 선택한 버튼, 기대 icon과 실제 icon root 활성 상태
- 성능 문제라면 Quest Profiler의 CPU/GPU frame time과 mirror 가시 여부

1. PPE 음성 흐름: 다른 상태로 이동하거나 거울 도착 시 진행 중인 Voice/SFX를 중지한다.
2. 방호복 Grab 음성은 현재 005 패널 음원만 사용하며, 음원이 비어 있으면 기존 Voice도 중지한다.
3. 방호복 미착용 상태의 장갑·장화 Grab 교육 음성을 차단한다. 방호복 착용 후 정상 장갑과 장화는 교육 모드에서 각각 최초 1회만 HowTo 음성을 재생한다.
4. 훈련·테스트 모드에서는 장화 교육 멘트를 재생하지 않는다.
5. 테이프를 먼저 사용한 뒤 다른 손 장갑을 착용해도 테이프 적용 모델이 표시되도록 수정했다.
6. 태블릿 체크리스트 완료 후 재활성화·재체크를 막았다.
7. PPE 래티클 고정 크기, 시작 지점 `Teleport_3_Exit`, 시작 지점 복귀 시 모드 선택 복귀 흐름을 반영했다.
8. 테스트 결과 숫자의 불필요한 앞자리 `0`을 제거했다.
9. PPE 교육/교육 모드/훈련 모드/테스트 모달 버튼을 저채도 계열로 조정하고 HDR 하이라이트를 낮췄다.
10. 조이스틱 클릭 미니 컨트롤러 가이드 `ControllerGuide_mini`를 왼쪽으로 이동했다.
11. `1_senario`·`1_EduChoice` 화면 흐름과 `2_mode` 설명·`2_Mode` 버튼 그룹을 모달 전환에 연결했다.
12. 교육·훈련·테스트 모드 설명 문구를 `2_mode` TMP에 반영했다.
13. `202`, `203` 및 PPE 시작 음원을 새 `.mp3` 파일로 교체했다.
14. `4_VO_PPE_EDU_002_PPE_Start.mp3` 이름 변경 후 Unity Inspector 참조가 새 GUID를 가리키는지 씬 저장 후 확인한다.
15. 오늘 변경된 씬·스크립트·음원 참조를 대상 씬 `3_PPE_Room_Train_Test_1.unity`에 반영했다.

### 테스트 체크리스트

1. 방호복 미착용 상태에서 장갑·장화를 잡아도 HowTo 교육 음성이 나오지 않는지 확인한다.
2. 방호복 착용 후 장갑 한쪽을 잡을 때 `HowToGloves`가 최초 1회만 재생되는지 확인한다.
3. 장화 한쪽을 잡을 때 `HowToBoots`가 최초 1회만 재생되는지 확인한다.
4. 방호복 → 장갑 한쪽 → 테이프 → 다른 손 장갑 순서에서 두 손 모두 테이프 모델로 표시되는지 확인한다.
5. 태블릿 체크 완료 후 같은 항목을 다시 Trigger/Grip해도 음성·체크가 반복되지 않는지 확인한다.
6. 교육/훈련/테스트 모달 버튼 색이 서로 구분되고 Hover/Pressed가 눈부시지 않은지 확인한다.
7. `Teleport_3_Exit` 마커가 보이고 시작 지점 복귀 시 모드 선택 모달이 표시되는지 확인한다.
8. 결과 화면에서 0분·0초·0점이 `0`으로 표시되는지 확인한다.
9. 음원 이름 변경 후 씬을 `Ctrl+S`로 저장하고 PPE 시작 VoiceStep의 Inspector 참조를 확인한다.

정적 검증은 `Assembly-CSharp.csproj` 빌드 오류 0개까지 완료했다. Quest/OpenXR 양안, 실제 XR Trigger/Grip, 음성 출력, 텔레포트 도착은 Unity Play Mode와 헤드셋에서 별도 확인해야 한다.
